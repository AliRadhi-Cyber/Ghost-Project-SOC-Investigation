1. EXECUTIVE SUMMARY

The Ghost Project was conducted as a controlled cybersecurity lab designed to simulate, detect, and investigate suspicious Windows authentication activity.

A local user account named GhostTest was created within a Windows 11 virtual machine. Two failed authentication attempts were recorded, followed by a successful login.

Windows Security Event Logs and PowerShell were used to identify and analyze Event IDs 4720, 4625, and 4624.

Evidence was collected and exported in EVTX and CSV formats. SHA256 hashes were generated and compared to verify evidence integrity. A chronological incident timeline was also reconstructed and validated.

The investigation determined that the observed activity was an authorized benign simulation. The reviewed events did not establish a malicious intrusion.

The project demonstrates practical SOC analyst skills in authentication monitoring, log analysis, event correlation, digital evidence preservation, and incident classification.




2. INVESTIGATION METHODOLOGY

1. Utilized a Windows 11 virtual machine within Oracle VirtualBox as a controlled cybersecurity testing environment.

2. Created a local test account named GhostTest.

3. Simulated two failed authentication attempts followed by a successful login.

4. Used PowerShell Get-WinEvent commands to retrieve Windows Security Event Logs.

5. Identified and analyzed the following Windows Security Event IDs:

   - 4720: User account creation.
   - 4625: Failed authentication.
   - 4624: Successful authentication.

6. Examined account names, logon types, authentication failure codes, source IP addresses, and process information.

7. Exported Windows Security Event Logs into EVTX and CSV evidence files.

8. Generated SHA256 cryptographic hashes using Get-FileHash.

9. Compared the calculated hashes against the saved hash records to verify evidence integrity.

10. Reconstructed and validated a chronological authentication timeline using PowerShell.

11. Evaluated the collected evidence and classified the activity as an authorized benign simulation.

- Source IP address: 127.0.0.1

- Failure Status: 0xC000006D
- Failure Substatus: 0xC000006A
- Failure Reason: Incorrect password
- Recorded failed authentication attempts: 2
- Recorded successful authentication attempts: 1

RISK ASSESSMENT

The investigated authentication events were consistent with authorized local testing.

The source IP address was identified as a loopback address, indicating local authentication activity rather than an external network connection for the examined events.

No unauthorized access or malicious intrusion was confirmed within the reviewed evidence.

Final Severity: Informational
Classification: Authorized Benign Simulation

SECURITY RECOMMENDATIONS

1. Monitor Windows Security Event IDs 4720, 4625, and 4624.

2. Configure SIEM alerts for repeated failed authentication attempts.

3. Correlate failed authentication attempts followed by successful logins.

4. Implement appropriate account lockout and password policies.

5. Regularly audit newly created local user accounts.

6. Enforce the principle of least privilege.

7. Maintain centralized security logging and appropriate log retention policies.

8. Preserve incident evidence and verify file integrity using SHA256 hashing.

RESPONSE DECISION

No containment or escalation was required because the observed activity was part of an authorized lab simulation.
